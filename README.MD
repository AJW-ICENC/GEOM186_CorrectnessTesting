# GEOM186: Functional Correctness Analysis

## Scope

This repository was created as part of an MSc GIS dissertation submitted to the University of Exeter.

The project forms part of the evaluation phase of a Design Science Research (DSR) study investigating the design, implementation and assessment of the Gaps and Overlaps (GaOs) service developed within IC-ENC.

The repository contains the automated dual-testing framework used to evaluate the functional correctness of the artefact during development, beta testing, and deployment.

---

## Purpose

The primary purpose of the project is to assess the functional correctness of 3 services within the DCAT architecture:

- Data Registration Service
- Database Management Service
- Overlap Assessment Service

The testing framework compares outputs generated by the DCAT infrastructure against authoritative reference datasets and existing operational processes.

These comparisons are used to determine whether outputs produced by the new service are functionally equivalent to those generated by the established process.

The assessment focuses on three key aspects of correctness:

- Record correctness
- Attribute correctness
- Geometry correctness

Differences identified during testing are captured and reported, enabling measurement of service performance and identification of defects throughout development.

---

## Methodology

The workflow follows a dual-testing approach in which outputs produced by the DCAT infrastructure are compared against authoritative reference sources including:

- Data Management Database (DMD)
- Existing QGIS-based operational workflows
- Baselined outputs from the live production process

The comparison process identifies:

- Missing records
- Additional records
- Attribute differences
- Geometry differences
- Overlap classification differences

From these results, service-specific accuracy metrics are generated and recorded over time.

The workflow was executed on a weekly basis throughout the development lifecycle to provide quantitative evidence of system performance and improvement.

---


### Main.py

`Main.py` contains the primary validation workflow responsible for executing all functional correctness checks.

The workflow:

- Connects to source databases
- Extracts authoritative reference data
- Extracts DCATs outputs
- Compares records, attributes and geometries
- Identifies discrepancies
- Produces detailed comparison reports
- Generates quantitative accuracy measures

The script includes validation functions for:

- Data Registration Service
- Database Management Service
- Overlap Assessment Service

---

### Scripts/

The `Scripts/` directory contains standalone analysis and visualisation scripts used to process outputs generated by `Main.py`.

These scripts are not part of the testing workflow and are primarily intended for:

- Dissertation analysis
- Statistical evaluation
- Figure generation
- Visualisation of testing results

Examples include:

- Data Registration dual-testing figures
- Database Management dual-testing figures
- Overlap Assessment dual-testing figures

---

### output/

Contains detailed comparison reports generated by the validation process.

These reports document identified issues including:

- Missing records
- Additional records
- Attribute mismatches
- Geometry mismatches

The outputs provide the evidence base from which performance metrics are derived.

---

### plots/

Contains figures generated from the processed testing data.

These figures are used to:

- Visualise service performance over time
- Assess development progress
- Support dissertation analysis
- Communicate evaluation results

---

### static/

Contains supporting reference data used by visualisation and analysis scripts.

Examples include:

- Sprint timelines

---


### Geometry Correctness

Assessment of whether spatial geometries generated by the service match authoritative spatial data.

Examples:

- Polygon correspondence
- Geometry validity
- Coordinate consistency
